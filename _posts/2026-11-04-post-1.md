## The Games
This year's oasis hosted at BITS had lots of competitions, from dance to rap to what not, however one of them caught my eye. The coding club was hosting a arcade game based competition, 6 classic games which almost everyone has played, score the most combined points and win.

The [site](https://arcade.bits-coding-club.in/) offers 6 classic games, now if you visit the website and try to play any one of the games, you will notice the error message in red, `Sign in and add a ticket to play`. Thing is, since the club itself has to make money off of the games, you need to buy tickets to play the games, one ticket allows you to play any one of the six games once. I was not going to be wasting money on tickets unless i could win and make it back. 

The page offers 6 games, the names are modified to make them sound cooler but they are, _Minesweeper_, _Wordle_, _Snake_, _Tetris_, _Pacman_ and _Flappy Bird_. I played some of them manually to get a feel for the games and realised that the total score was not a sum of the scores you got in the various games, their was some other internal algorithm. I would have to figure out which game offered the most amount of points into the total sum, while also being automatable. So i could actually enjoy oasis rather than sitting in my room playing the arcade all day.

Finally I settled on Wordle.

## The Rules
Now the game which I chose is not called _Wordle_ on the page it is reffered to as _Fastfind_. The reason for this are certain rules which the game has:
1. You have 2 minutes to solve as many words as possible, pausing the clock is not possible.
2. You get 6 tries per word, then the next word rolls in.
3. If you solve the word your time increases by 10 seconds + the number of green tiles you found.

This keeps going on until either you run out of time or you solve 50 words in 2 minutes, which is the max number of words you can solve, the UI is quite intuitive and looks as follows.

## The Idea
Now obviously i was not gonna grind Wordle for 4 days straight trying to win the thing, no i was going to write a bot which could it solve everything for me. Now what are the problems we need to solve, the first and foremost is how do we find/make a bot which solves wordle insanely fast, secondly how would i automate the typing of words and also taking the input from the site regarding which words are correct and in the wrong position, correct and in the right position and not in the word.

The latter is much easier, typing out words can be done using `pyautogui` and reading the colours and letters can be accomplished using a combination of `opencv` and `numpy`. The former however, is much tougher. Creating a bot which can solve wordles as fast as possible is no easy task, however I did remember a 3blue1brown [video](https://www.youtube.com/watch?v=v68zYyaEmEA) in which he solves wordle using information theory, I had completely watched the video and figured I could implement a bot myself, since 3b1b had made the code opensource itself.  

However, upon googling I found someone who had done it before me, now obviously I would not be wasting time implementing the bot, [this](https://github.com/ybenhayun/wordlebot) Github repo had the source code for a website which could solve any word in average of $3.4212$ guesses, which is bollocks compared to the average human being. You can play around with the bot [here](https://ybenhayun.github.io/wordlebot/) yourself. This was just what I was looking for, but instead of a website I would hook into the internal logic of the site and connect that to my `opencv/numpy` screen reader.
## The Bot
First I cloned the above repo and created a CLI tool which interfaces with the internal code, the code itself expects data for the guesses from the DOM of the page, so the CLI tool is in javascript since this allows us to a _fake_ the DOM. 

The CLI tool also classifies the words on the basis of likely solves and unlikely solves, the data for which comes from the internals of the worlde bot repo itself. To explain how the CLI tool is utilised look at the following example,
```
node wordle-cli.js --json SALET:BBBGG BURIN:BBGBB
```
The words are our guesses and the codes corresponding to them represent the colours of the squares which provides information about the state of each word in the guess. Whether it is black, green or yellow. This info is then passed to the wordle bot using a fake DOM, which then gives us the output, which we read. 

For the above example the output looks like the following,
```
{"guessesUsed":2,"guessesLeft":4,"status":"ok","recommendation":"EGRET","alternatives":[{"word":"EGRET"}],"likelyCount":1,"unlikelyCount":1,"remaining":["EGRET","MPRET"],"likelyAnswers":["EGRET"],"unlikelyAnswers":["MPRET"]}
```

The python bot reads this JSON and tries the recommendation, and then passes the input from the website about the recommendation to the bot until it suggests a solution or multiple, which it loops through until the __SOLVED__ counter on the page increments and then it resets the bot and starts solving from scratch again.

The python bot itself has quite a few functions, the main logic was written by me, but most of the debugging code has been written by Claude. There is a calibrate function which can be accessed using the `--calibrate` switch, it gives the user instructions to move their mouse to the top right and top left of the grid which contains the words, and to the top left and top right of the region containing the __SOLVED__ counter which is necessary to know when to reset the guesses.

The `tile_state` function calculates the state of each tile in the grid assigning it a colour if it has a letter or assigning it to `.` when it's empty and to `?` when it can't read the tile properly. The `board_state` function runs this on every single tile. The `counter_mask` and `counter_changed` functions run to check whether the counter has incremented since this tells us that the word has been solved successfully. 

Now one might be thinking, where in the code is the logic for reading the words from the screen using `opencv`, it seems to be absent. I thought of this earlier as well when writing the bot, then I realised i don't need to read it off the screen, I only need to read the colours. The bot already knows the words since it was the one who typed them! The words are saved using `history.append((word, feedback))`  in the code.

The bot passes the states to the wordle CLI tool which internally passes it to the wordle bot, which provides us with the next best guess, until the bot sees the __SOLVED__ counter increment and then it resets the history of guesses and starts all over again.

One of the caveats of the bot is it can only start when the grid is completely empty, i have not coded it to be able to pick off in the middle of solving a word. There is also a `--snapshot` functionality which allows it to take a screen shot and show the state of the grid. 
```
$ python3 worlde_cv_bot.py --snapshot
Snapshot: wordle_cv_debug.png | row states: ['YBBGG', 'BBYBB', '.....', '.....', '.....', '.....']
```
This can be used for debugging to see if re-calibration is necessary.
## The Result
The final result is a wordle bot which can solve any word in under 5 seconds, and since the game gives you a minimum of 10 seconds for each word it never runs out of time. Thus it can solve all 50 words without running out of time ever, giving me a monstrous amount of points.
